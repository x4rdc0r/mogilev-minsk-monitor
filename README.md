# Мониторинг мест: Могилёв → Минск (mogilevminsk.by)

Скрипт проверяет свободные места на маршрутке Могилёв → Минск на заданную дату
в заданном окне времени и присылает уведомление в Telegram, когда место
освобождается (отказ, снятие брони и т.п.).

Текущая настройка: **08.11.2026 (вс), 16:30–20:00, Могилёв → Минск**.

## Как это работает

Сайт `mogilevminsk.by` — Angular-приложение, которое берёт данные из открытого
JSON-эндпоинта:

```
POST https://mogilevminsk.by/timetable/trips/
Content-Type: multipart/form-data

date=2026-11-08&from_city=2&dest_city=1
```

Города: `2` = Могилёв, `1` = Минск. Ответ содержит рейсы с полями
`departure_time`, `free_seats`, `all_seats`, `route_id`.

Особенности данных:

- `free_seats >= 1` — место есть, `0` — мест нет, отрицательное — мест нет
  (перебор/предварительные брони);
- сайт отдаёт число мест **с потолком 2** — «2» означает «два и более»;
- расписание публикуется на ~10–14 дней вперёд, поэтому монитор нужно
  запускать заранее (для 08.11 рейсы уже есть).

Монитор только уведомляет. Бронирование — вручную: на сайте
(форма брони, требует SMS-код) или по телефонам 788-55-33, 788-66-33.

## Локальный запуск

Нужен только Python 3.9+ (внешних зависимостей нет).

```powershell
# посмотреть текущую доступность
python monitor.py --show

# проверка без отправки в Telegram
python monitor.py --dry-run

# обычная проверка (+ уведомление, нужен TELEGRAM_BOT_TOKEN)
$env:TELEGRAM_BOT_TOKEN="123456:ABC..."
python monitor.py
```

## Telegram-бот

1. В Telegram открыть [@BotFather](https://t.me/BotFather) → `/newbot` →
   получить токен вида `123456789:AA...`.
2. Написать своему боту любое сообщение (`/start`) — это нужно, чтобы
   скрипт смог определить `chat_id` (либо задайте `TELEGRAM_CHAT_ID` вручную).
3. Проверить отправку: `$env:TELEGRAM_BOT_TOKEN="..."; python monitor.py --dry-run`
   убирает префикс `--dry-run`, чтобы отправить реально.

Удобнее держать токен локально в файле `.env.local` (он в `.gitignore`
и не попадёт в репозиторий):

```
TELEGRAM_BOT_TOKEN=123456789:AA...
```

Скрипт сам подхватит его при запуске.

Секреты не коммитятся: токен передаётся только через переменные окружения
и GitHub Secrets.

## Запуск в GitHub Actions (24/7, бесплатно)

```powershell
# 1. Авторизоваться в GitHub
gh auth login

# 2. Создать приватный репозиторий и запушить код
git init
git add .
git commit -m "seat monitor"
gh repo create mogilev-minsk-monitor --private --source . --push

# 3. Добавить секреты
gh secret set TELEGRAM_BOT_TOKEN --body "123456:ABC..."
# необязательно, если бот уже получал сообщения от вас:
gh secret set TELEGRAM_CHAT_ID --body "123456789"

# 4. Запустить вручную и посмотреть результат
gh workflow run monitor.yml
gh run watch
```

Дальше workflow `Seat monitor` запускается по расписанию каждые 5 минут.
Расписание задаётся в `.github/workflows/monitor.yml` (cron в UTC).

Если workflow падает (сайт недоступен, изменился API), GitHub пришлёт
письмо — молчаливого молчания не будет.

## Быстрый локальный вариант (пока ПК включён)

GitHub cron даёт интервал ~5 минут и иногда задерживается. Если нужна реакция
за секунды, запустите тот же скрипт локально — он опрашивает каждые 45 секунд
и пишет состояние в отдельный файл `state.local.json`:

```powershell
$env:TELEGRAM_BOT_TOKEN="123456:ABC..."
.\run_local.ps1              # опрос каждые 45 с
.\run_local.ps1 -IntervalSeconds 30
```

Оба варианта можно держать включёнными одновременно — они не мешают друг другу
(разные файлы состояния), просто уведомления могут прийти дважды.

## Настройка

Параметры задаются переменными окружения (значения по умолчанию — в скобках):

| Переменная | Значение |
|---|---|
| `TARGET_DATE` | дата поездки, `YYYY-MM-DD` (`2026-11-08`) |
| `FROM_CITY` | город отправления (`2` — Могилёв) |
| `DEST_CITY` | город назначения (`1` — Минск) |
| `WINDOW_START` | начало окна времени (`16:30`) |
| `WINDOW_END` | конец окна времени (`20:00`) |
| `MIN_FREE_SEATS` | минимально нужное число мест (`1`) |
| `TELEGRAM_BOT_TOKEN` | токен бота |
| `TELEGRAM_CHAT_ID` | id чата (если не задан — определяется автоматически) |
| `STATE_FILE` | файл состояния (`state.json`) |

В GitHub Actions эти переменные задаются в блоке `env:` шага «Проверка мест».

## Файлы

- `monitor.py` — весь мониторинг (stdlib, ретраи, антиспам по состоянию).
- `state.json` — какие рейсы уже были доступны: чтобы не присылать одно и то же
  каждые 5 минут, workflow коммитит файл обратно в репозиторий.
- `.github/workflows/monitor.yml` — запуск по cron + ручной запуск.
- `run_local.ps1` — локальный цикл с интервалом 45 с (опционально).
- `.gitignore`
