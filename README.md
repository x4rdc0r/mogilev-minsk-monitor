# Мониторинг мест Могилёв ⇄ Минск + Telegram-бот с меню

Бот следит за свободными местами на маршрутках Могилёв ⇄ Минск на трёх сайтах
и присылает уведомление, когда место освобождается. Настройки (даты,
направление, окна времени) задаются кнопками прямо в Telegram.

| Источник | Как получаем данные |
|---|---|
| `mogilevminsk.by` | JSON-API платформы Transporter: `POST /timetable/trips/` |
| `avto-slava.by` | та же платформа и тот же API, другая база перевозчика |
| `atlasbus.by` | Next.js: рейсы на дату лежат в `__NEXT_DATA__` страницы `?date=` |

## Бот

[@monitor_travelsMM_bot](https://t.me/monitor_travelsMM_bot)

```
🚌 Мониторинг мест

📅 Даты: 08.11 вс
🧭 Направление: Могилёв → Минск
🕐 Время: 16:30–20:00
🟢 Мониторинг: включён

[📅 Даты]            [🧭 Направление]
[🕐 Время]           [⏸ Выключить]
[📊 Свободно сейчас] [🔄 Проверить]
```

- **📅 Даты** — 14 дней вперёд, можно отметить до 3.
- **🧭 Направление** — переключатель `Могилёв → Минск` ⇄ `Минск → Могилёв`.
- **🕐 Время** — пресеты или свой вариант текстом: `16:30-18:00, 19:00-20:00`
  (до двух окон).
- **📊 Свободно сейчас** — сводка по последней проверке (до 2–3 минут давности).
- **🔄 Проверить** — внеочередной запуск монитора.
- **⏸ Выключить** — пауза, настройки при этом сохраняются.

Команды: `/menu`, `/status`, `/check`, `/help`.

Настройки хранятся в `config.json` в репозитории — бот их читает и пишет сам,
поэтому они переживают перезапуск.

## Архитектура

```
Telegram ──long-polling──> bot.py (GitHub Actions, непрерывная цепочка)
                              │ читает/пишет config.json (git)
                              └──Actions API──> внеочередная проверка

GitHub Actions (цепочка) ──> monitor.py каждые 150 с ──> уведомления в Telegram
                                                        └─> state.json (git)
```

Бот и монитор — обычные Python-скрипты без внешних зависимостей, работают
на стандартной библиотеке.

Cron в GitHub ненадёжен (запуски опаздывают и иногда теряются), поэтому оба
workflow работают «эстафетой»: каждый прогон длится ~5 ч 45 мин, затем перед
завершением ставит в очередь следующий запуск того же workflow. Проверки идут
каждые 150 секунд, бот доступен постоянно, простой при передаче — несколько
секунд. Cron раз в 6 часов оставлен как страховка: если цепочка оборвётся,
он поднимет её снова.

Кнопка «🔄 Проверить» перезапускает цепочку монитора (новый запуск отменяет
текущий), поэтому проверка происходит сразу, а не после окончания цикла.

## Локальный запуск

```powershell
# проверка по текущим настройкам
python monitor.py

# показать доступность по всем источникам
python monitor.py --show

# бот локально (настройки пишутся в config.json, без git)
python bot.py --local
```

Токен бота хранится в `.env.local` (файл в `.gitignore`):

```
TELEGRAM_BOT_TOKEN=123456789:AA...
```

## config.json

```json
{
  "enabled": true,
  "dates": ["2026-11-08"],
  "direction": "mogilev-minsk",
  "windows": [{"start": "16:30", "end": "20:00"}],
  "min_free_seats": 1
}
```

- `direction`: `mogilev-minsk` или `minsk-mogilev`.
- `windows`: до двух окон, пустой список — любое время.
- `dates`: до 3 дат в формате `YYYY-MM-DD`; пустой список — мониторинг молчит.

## GitHub Actions

| Workflow | Что делает |
|---|---|
| `Seat monitor` | непрерывная цепочка: проверка каждые 150 с, уведомления, `state.json` |
| `Bot menu` | непрерывная цепочка: long-polling бота с меню |

Проверить вручную:

```powershell
gh workflow run monitor.yml --repo x4rdc0r/mogilev-minsk-monitor
gh workflow run bot.yml --repo x4rdc0r/mogilev-minsk-monitor
gh run list --repo x4rdc0r/mogilev-minsk-monitor --limit 5
```

Секреты репозитория: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.

## Оформление бота

```powershell
python bot_profile.py   # имя, описания, команды, кнопка меню
```

Аватар меняется только через @BotFather, `@username` — только созданием нового бота.

## Особенности данных

- `mogilevminsk.by` отдаёт число мест **с потолком 2**, `avto-slava.by` — с потолком 4:
  бот показывает `≥2 места` / `≥4 места`. Ноль и отрицательные значения — мест нет.
- `atlasbus.by` отдаёт настоящее число мест.
- Расписание публикуется на ~10–14 дней вперёд.
- Монитор только уведомляет: бронь — на сайте (может требовать SMS-код)
  или по телефонам 788-55-33, 788-66-33.

## Файлы

- `monitor.py` — проверки, фильтры, уведомления, `state.json`.
- `bot.py` — меню и обработка кнопок, запись `config.json`.
- `bot_profile.py` — оформление профиля бота.
- `config.json` — настройки мониторинга.
- `state.json` — что было свободно на последней проверке.
- `.github/workflows/monitor.yml`, `.github/workflows/bot.yml` — расписания.
- `run_local.ps1` — локальный цикл монитора (опционально).
